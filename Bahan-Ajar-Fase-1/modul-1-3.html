Sub-Topik 1.3.1

Simulator vs Emulator: Cisco Packet Tracer vs GNS3

Mengapa engineer profesional dan peserta Lomba LKS beralih dari Packet Tracer ke emulator GNS3 / EVE-NG?

Blok 1 - Masalah Nyata di Lapangan

Di sekolah, kamu sangat mahir menggunakan Cisco Packet Tracer. Namun saat kamu mulai magang di ISP atau mencoba menghubungkan router Cisco dengan router MikroTik dan Server Debian nyata, kamu mendapati bahwa Packet Tracer TIDAK BISA menambahkan router MikroTik dan banyak perintah CLI memunculkan error % Invalid command.

Pertanyaan: Kenapa Packet Tracer memiliki batasan tersebut, dan mengapa para profesional menggunakan software seperti GNS3 atau EVE-NG untuk mendesain jaringan skala industri?

Perbedaannya terletak pada status: Packet Tracer adalah SIMULATOR buatan, sedangkan GNS3 adalah EMULATOR yang menjalankan Kernel OS Asli!

Blok 2 - Konsep Inti & Definisi
Definisi Simulator vs Emulator:

Network Simulator (Packet Tracer) adalah program perangkat lunak yang memprogram perilaku jaringan secara tiruan (sintetis). Software ini hanya membalas perintah-perintah yang sudah di-coding oleh pembuatnya.
Network Emulator (GNS3 / EVE-NG) adalah platform virtualisasi perangkat keras (hardware virtualization via QEMU, KVM, Dynamips) yang memutar Image Sistem Operasi ASLI (Cisco IOS .bin/qcow2, MikroTik RouterOS .vmdk, Linux Kernel, Windows Server).

Analogi Game Pesawat vs Simulator Kokpit Pilot Asli:
  • Packet Tracer = Game HP simulasi terbang. Grafiknya bagus dan mudah dimainkan pemula, tetapi jika ada tombol kokpit yang tidak diprogram pengembang game, tombol itu tidak bisa dipencet.
  • GNS3 / EVE-NG = Ruang Simulator Kokpit Resmi Akademi Penerbangan. Di dalamnya dipasang instrumen pesawat asli dari pabrik Boeing/Airbus. Setiap saklar, tuas, dan respon instrumen bekerja 100% sama dengan pesawat asli di udara.

Pengenalan MikroTik RouterOS & Winbox MNDP Discovery

Bagaimana aplikasi Winbox dapat mendeteksi dan me-remote router MikroTik baru secara ajaib via Layer 2 MAC Address tanpa perlu setting IP?

Blok 1 - Masalah Nyata di Lapangan

Kamu baru saja membeli router MikroTik hEX (RB750Gr3) baru dari toko. Kamu mereset router tersebut ke pengaturan kosong (No Default Configuration). Router tersebut tidak memiliki alamat IP sama sekali (0.0.0.0). Laptopmu juga belum disetting IP statis.

Pertanyaan: Pada perangkat Cisco atau router biasa, kamu harus memasang kabel console serial khusus atau menyamakan IP subnet di laptopmu agar bisa masuk. Tapi kenapa pada MikroTik, kamu cukup membuka aplikasi Winbox dan router langsung terdeteksi dan bisa di-login hanya dalam 1 detik?

Rahasia luar biasa ini bernama MNDP (MikroTik Neighbor Discovery Protocol) dan fitur MAC-Winbox yang bekerja di Layer 2 (Data Link)!

Blok 2 - Konsep Inti & Definisi
Definisi RouterOS & Winbox MNDP:

MikroTik RouterOS adalah sistem operasi berbasis Linux kernel yang dirancang khusus untuk mengubah komputer atau hardware RouterBOARD menjadi router jaringan enterprise yang kaya fitur (Routing, Firewall, Bandwidth Queue, Hotspot, VPN).
Winbox adalah aplikasi administrasi GUI resmi berbasis Windows (bisa dijalankan di Linux/macOS via Wine) yang memiliki kemampuan Layer 2 MAC-Telnet / MAC-Winbox menggunakan protokol discovery MNDP (Port UDP 5678).

Analogi Memanggil Nama Teman di Ruangan Gelap:
  • Login via IP Address (Layer 3) = Menghubungi teman lewat nomor telepon resmi. Kamu harus tahu nomor teleponnya dan pulsamu harus aktif di jaringan yang sama.
  • Login via MAC Address (Layer 2 MNDP) = Berada di ruangan yang sama dan berteriak: "Halo, siapa saja router yang ada di sini?". MikroTik langsung menjawab dengan nomor KTP fisiknya (MAC Address), dan kamu bisa langsung mengajaknya bicara tanpa butuh nomor telepon (IP)!

Fitur Unggulan MikroTik

DHCP Server & Alur Negosiasi Otomatis DORA

Bagaimana mekanisme Discover, Offer, Request, dan Acknowledge membagikan IP Address ke ratusan perangkat dalam hitungan milidetik?

Blok 1 - Masalah Nyata di Lapangan

Sebuah kafe kopi kekinian memiliki 200 pelanggan datang dan pergi setiap hari. Semua pelanggan ingin langsung terhubung ke WiFi kafe untuk membuka laptop dan smartphone.

Pertanyaan: Jika setiap kali pelanggan datang, barista kafe harus meminjam HP pelanggan untuk mengetikkan IP Address, Subnet Mask, Gateway, dan DNS secara manual, berapa lama antrean kafe akan macet? Dan apa yang terjadi jika ada dua pelanggan yang salah ketik IP yang sama (IP Conflict)?

Solusinya adalah mengaktifkan DHCP Server (Dynamic Host Configuration Protocol) yang menangani seluruh alokasi IP secara otomatis dan bebas tabrakan melalui siklus DORA!

Blok 2 - Konsep Inti & Definisi
Definisi DHCP & Siklus DORA:

DHCP (Dynamic Host Configuration Protocol) adalah protokol jaringan client-server berbasis UDP (Port 67 Server / 68 Client) yang secara dinamis mendistribusikan konfigurasi IP Address, Subnet Mask, Default Gateway, dan DNS Server ke perangkat klien.
Siklus DORA adalah 4 tahap jabat tangan (handshake) standar dalam negosiasi DHCP:
1. Discover (Broadcast): Klien mencari keberadaan DHCP server di LAN.
2. Offer (Unicast/Broadcast): Server menawarkan satu IP yang tersedia dari IP Pool.
3. Request (Broadcast): Klien menyetujui tawaran IP tersebut.
4. Acknowledge (Unicast/Broadcast): Server mengunci sewa (Lease) dan mengesahkan IP ke klien.

Analogi Check-In Kamar Hotel:
  • 1. Discover = Tamu baru masuk ke lobi hotel dan berteriak: "Halo resepsionis, adakah kamar kosong untuk saya?".
  • 2. Offer = Resepsionis memeriksa daftar kamar dan berkata: "Ada kamar No. 50 kosong untuk Anda!".
  • 3. Request = Tamu menjawab: "Oke, saya setuju mengambil kamar No. 50 tersebut!".
  • 4. Acknowledge = Resepsionis menyerahkan kunci kamar, mencatat nama tamu di buku registrasi, dan menetapkan batas waktu sewa (Lease Time).

4.1 Konfigurasi DHCP Server di MikroTik RouterOS vs Cisco IOS:

️ Perangkat: MikroTik RouterOS & Cisco Router 2911 Konfigurasi: IP Pool, Network, dan DHCP Server Tujuan: Membagikan IP 192.168.88.10-100 dengan Lease Time 1 Jam
CLI MikroTik vs Cisco DHCP Setup 
=== KONFIGURASI DI MIKROTIK ROUTEROS ===
# 1. Buat rentang IP Pool
/ip pool add name=dhcp_pool_lan ranges=192.168.88.10-192.168.88.100

# 2. Definisikan informasi gateway & DNS
/ip dhcp-server network add address=192.168.88.0/24 gateway=192.168.88.1 dns-server=8.8.8.8,1.1.1.1

=== KONFIGURASI DI CISCO IOS ===
Router(config)# ip dhcp excluded-address 192.168.88.1 192.168.88.9
Router(config)# ip dhcp pool LAN_POOL
Router(dhcp-config)# network 192.168.88.0 255.255.255.0
Router(dhcp-config)# default-router 192.168.88.1
Router(dhcp-config)# dns-server 8.8.8.8

Blok 5 - Studi Kasus Nyata

Kasus: Bencana "IP Pool Exhaustion" di Kafe Mall

Troubleshooting Nyata

Gejala: Sebuah kafe memiliki subnet 192.168.1.0/24 (Tersedia 250 IP). Pada jam 14.00 siang, pelanggan yang baru datang komplain bahwa HP mereka tidak bisa terhubung ke WiFi dan stuck di status "Obtaining IP Address...", padahal pengunjung di dalam kafe hanya ada 30 orang.

1
Penyebab (Root Cause):

Saat dicek di /ip dhcp-server lease print, seluruh 250 IP penuh status bound karena nilai Lease Time diatur ke 3 Hari (3d)! Pelanggan yang kemarin sudah pulang masih menahan hak sewa IP tersebut di router.

2
Solusi Cepat:

Teknisi mengubah Lease Time menjadi 30 Menit (30m). Begitu pengunjung pergi dan tidak memperbarui sewa, IP otomatis ditarik kembali ke pool untuk diberikan ke pengunjung baru!

Aturan Pemilihan Lease Time:
• Hotspot Umum / Kafe / Bandara = 15-30 Menit (Pengunjung dinamis).
• Kantor Perusahaan = 1-3 Hari (Karyawan tetap).
Blok 6 - Quest Uji Pemahaman
Quest 1.3.3 • Pilihan Ganda 10 Poin

Manakah urutan kronologis yang BENAR dari 4 paket dalam proses negosiasi DHCP (DORA)?

v Jawaban Benar: C (Discover -> Offer -> Request -> Acknowledge)

Pembahasan: Jembatan keledai untuk menghafal siklus DHCP adalah D-O-R-A (Discover dari client, Offer dari server, Request dari client, Acknowledge dari server).

Sering Keliru (Miskonsepsi Umum):

Banyak yang mengira paket DHCP Request dikirim secara unicast langsung ke server. DHCP Request tetap dikirim secara BROADCAST agar jika ada DHCP Server cadangan lain di jaringan yang sama, server cadangan tersebut tahu tawarannya ditolak dan bisa menarik kembali IP-nya.

  • Estimasi Waktu: 25 Menit.
  • Poin Kunci: Tunjukkan menu IP -> DHCP Server -> Leases di Winbox. Tunjukkan bagaimana ikon 'D' (Dynamic) muncul saat HP terhubung.
  • Trik Praktis: Ajarkan cara membuat IP Static Binding (mengunci IP tertentu ke MAC PC printer agar IP-nya tidak berubah).
Sub-Topik 1.3.4

NAT (Network Address Translation) & Masquerade (PAT)

Bagaimana ribuan perangkat ber-IP privat lokal bisa berselancar di internet secara bersamaan menggunakan 1 alamat IP publik?

Blok 1 - Masalah Nyata di Lapangan

Di seluruh dunia, alokasi total IPv4 hanya berjumlah 4,29 miliar alamat dan sudah resmi habis. Sebuah kantor memiliki 300 komputer dengan IP privat lokal 192.168.1.0/24. Router ISP Telkom/IndiHome hanya menyewakan 1 buah IP Publik (misal 203.0.113.88).

Pertanyaan: Alamat IP privat (seperti 192.168.x.x) mutlak DITOLAK dan DIBUANG oleh router internet publik. Bagaimana caranya agar ke-300 komputer tersebut bisa membuka YouTube, Google, dan Instagram secara serentak hanya dengan bermodalkan 1 IP publik tersebut?

Jawabannya adalah NAT Masquerade / PAT (Port Address Translation) yang meminjamkan nomor port Layer 4 untuk membedakan ribuan sesi lalu lintas!

Blok 2 - Konsep Inti & Definisi
Definisi NAT & Masquerade (PAT):

NAT (Network Address Translation) adalah metode pemetaan alamat IP dengan mengubah informasi alamat IP sumber (Source IP) atau tujuan (Destination IP) pada header paket IP saat melintasi router.
NAT Masquerade / PAT (Port Address Translation / Overload) adalah bentuk dinamis dari Source NAT (Src-NAT) yang memungkinkan ribuan perangkat IP privat berbagi 1 IP publik dinamis yang sama, dengan cara memetakan kombinasi unik [IP Privat : Port Asal] -> [IP Publik : Port NAT Baru] pada tabel pelacakan koneksi (Connection Tracking Table).

Analogi Pesanan Barang Melalui Resepsionis Kantor:
  • 300 Karyawan (IP Privat) = 300 karyawan di dalam gedung kantor. Kurir luar tidak boleh masuk ke dalam ruangan kantor demi keamanan.
  • Alamat Kantor Resmi (IP Publik) = Alamat Gedung Menara Mandiri No. 88 (Hanya ada 1 alamat resmi di peta).
  • Nomor Ekstensi / Loker (Port NAT) = Setiap kali Arya memesan barang, dia menulis alamat gedung + Ekstensi Meja #101. Saat Budi memesan barang, dia menulis alamat gedung + Ekstensi Meja #102.
  • Saat paket tiba dari kurir eksternal, resepsionis (Router NAT) membaca nomor ekstensi dan mengantarkannya ke meja karyawan yang tepat!

4.1 Konfigurasi NAT Masquerade & Port Forwarding di MikroTik RouterOS:

️ Perangkat: MikroTik RouterOS v7 Menu: /ip firewall nat Tujuan: Mengaktifkan Masquerade Internet + Port Forwarding Dst-NAT CCTV (Port 8080 -> 80)
/ip firewall nat 
# 1. ATURAN MASQUERADE (Agar semua PC LAN bisa akses internet):

Blok 5 - Studi Kasus Nyata

Kasus: Akses Kamera CCTV Gudang dari Smartphone Pemilik via Dst-NAT

Implementasi Praktik Industri

Kebutuhan: Pemilik pabrik memiliki DVR CCTV di LAN kantor dengan IP 192.168.88.200:8000. Pemilik ingin memantau CCTV dari HP saat sedang liburan di luar negeri.

1
Solusi dengan Destination NAT (Dst-NAT):

Router MikroTik dikonfigurasi: /ip firewall nat add chain=dstnat in-interface=ether1 protocol=tcp dst-port=8000 action=dst-nat to-addresses=192.168.88.200 to-ports=8000.

2
Hasil Akses:

Pemilik membuka aplikasi CCTV di HP dengan memasukkan alamat IP Publik kantor 203.0.113.88:8000. Router MikroTik secara mulus membelokkan paket masuk tersebut langsung ke DVR CCTV lokal!

Bedakan Src-NAT vs Dst-NAT:
• Src-NAT (Masquerade): Mengubah IP Asal (Dipakai agar klien LAN bisa keluar ke internet).
• Dst-NAT (Port Forwarding): Mengubah IP Tujuan (Dipakai agar orang luar internet bisa mengakses server di dalam LAN).
Blok 6 - Quest Uji Pemahaman
Quest 1.3.4 • Pilihan Ganda 10 Poin

Jika sebuah kantor ingin mempublikasikan Server Web internal (IP 192.168.88.10:80) agar bisa diakses oleh pelanggan dari seluruh dunia melalui IP Publik router, tipe NAT manakah yang harus dikonfigurasi?

v Jawaban Benar: B (Destination NAT / Dst-NAT)

Pembahasan: Karena paket datang dari luar menuju IP Publik router, router harus mengubah Destination IP paket tersebut menjadi IP privat Server Web lokal (192.168.88.10). Ini adalah fungsi dari Destination NAT (Dst-NAT).

Sering Keliru (Miskonsepsi Umum):

Banyak pemula mengira perintah action=masquerade membutuhkan penulisan IP publik secara manual. Masquerade dirancang khusus untuk IP publik yang berubah-ubah (Dinamis). Router akan otomatis mendeteksi IP publik mana yang sedang aktif di interface WAN tersebut.

Catatan Mentor (Klik untuk Buka/Tutup) ▼
  • Estimasi Waktu: 30 Menit.
  • Poin Kunci: Tunjukkan menu IP -> Firewall -> Connections di Winbox saat laptop membuka YouTube. Tunjukkan ribuan baris pemetaan IP:Port yang sedang berlangsung realtime.
Sub-Topik 1.3.5

Interkoneksi Multi-Vendor: Cisco IOS ↔ MikroTik RouterOS

Bagaimana membangun pertukaran rute otomatis OSPF antar dua router dari pabrikan raksasa yang berbeda?

Blok 1 - Masalah Nyata di Lapangan

Di ISP tempatmu bekerja, Router Core di Data Center menggunakan Cisco Catalyst / ASR Series karena keandalan hardware-nya yang tinggi. Namun di sisi pelanggan perumahan/kantor cabang, perusahaan memasang MikroTik Cloud Core Router (CCR) karena efisiensi biaya.

Pertanyaan: Kedua router memiliki sistem operasi yang sangat berbeda (Cisco IOS vs MikroTik RouterOS). Protokol routing dinamis apa yang bisa berjalan di antara keduanya tanpa terjadi bentrok bahasa vendor?

Kuncinya adalah menggunakan Standar Terbuka IETF (Open Standard) seperti OSPF (Open Shortest Path First)!

Blok 2 - Konsep Inti & Definisi
Definisi Multi-Vendor Peering:

Multi-Vendor Peering adalah proses interkoneksi dan pertukaran informasi routing antar perangkat jaringan dari manufaktur yang berbeda menggunakan protokol standar internasional yang disepakati bersama oleh konsorsium IETF/IEEE.
Syarat Mutlak OSPF Multi-Vendor Adjacency:
• Area ID harus sama persis (misal sama-sama Area 0 / Backbone).
• Subnet Mask & Link IP harus berada di subnet yang sama (misal 10.10.10.0/30).
• Hello Interval & Dead Interval harus cocok (Default: 10s Hello, 40s Dead).
• MTU Interface harus bernilai sama persis (Default Ethernet: 1500 bytes).

Router(config-router)# network 192.168.1.0 0.0.0.255 area 0

=== 2. KONFIGURASI DI SISI MIKROTIK ROUTEROS V7 ===
/ip address add address=10.10.10.2/30 interface=ether1 comment="Link to Cisco"
/routing ospf instance add name=ospf-inst router-id=2.2.2.2 disabled=no
/routing ospf area add name=backbone instance=ospf-inst area-id=0.0.0.0
/routing ospf interface-template add area=backbone networks=10.10.10.0/30
/routing ospf interface-template add area=backbone networks=192.168.2.0/24

Blok 5 - Studi Kasus Nyata

Kasus: Masalah "OSPF Stuck in ExStart / Exchange" Karena MTU Mismatch

Troubleshooting Klasik Multi-Vendor

Gejala: Teknisi menghubungkan Cisco dan MikroTik. Status OSPF tidak pernah bisa mencapai FULL, melainkan stuck di status ExStart/Exchange.

1
Pemeriksaan Nilai MTU:

Pada interface Cisco, MTU bernilai 1500 bytes. Namun pada port MikroTik SFP fiber optik, teknisi menyetel MTU 9000 bytes (Jumbo Frame).

2
Solusi:

OSPF menolak bertukar database topologi jika nilai MTU antar kedua ujung kabel berbeda. Samakan MTU MikroTik menjadi 1500 bytes (atau tambahkan ip ospf mtu-ignore di interface Cisco). Dalam 3 detik, status OSPF langsung melompat ke FULL!

Blok 6 - Quest Uji Pemahaman
Quest 1.3.5 • Pilihan Ganda 10 Poin

Manakah yang BUKAN merupakan syarat mutlak agar router Cisco dan router MikroTik bisa membentuk OSPF Neighbor Adjacency (State FULL)?

v Jawaban Benar: B

Pembahasan: OSPF adalah Open Standard Protocol. OSPF dirancang secara sengaja agar perangkat beda merk (Cisco, MikroTik, Huawei, Juniper) bisa saling berkomunikasi asalkan parameter teknisnya (Area, Timer, Subnet, MTU) cocok.

Sering Keliru (Miskonsepsi Umum):

Banyak siswa mencoba menjalankan protokol EIGRP antara Cisco dan MikroTik lalu heran kenapa tidak jalan. EIGRP adalah protokol eksklusif (proprietary) milik Cisco, sehingga tidak didukung oleh sebagian besar vendor router lain. Gunakan OSPF untuk koneksi multi-vendor.

  • Estimasi Waktu: 30 Menit.

Sub-Topik 1.3.6

Firewall Filter Rules Dasar di MikroTik RouterOS

Bagaimana memahami Input Chain vs Forward Chain untuk mengunci router dari serangan hacker luar sekaligus mengamankan LAN?

Blok 1 - Masalah Nyata di Lapangan

Begitu router MikroTik kantor diberi IP Publik internet, dalam waktu kurang dari 5 menit log routermu (/log print) akan dibanjiri ribuan percobaan login gagal dari robot hacker di internet yang menembak port SSH (22), Telnet (23), dan Winbox (8291).

Pertanyaan: Jika router tidak dilindungi firewall, CPU router akan mencapai 100% dan hacker bisa membajak routermu. Bagaimana cara memblokir semua serangan hacker dari internet menuju router, tanpa mengganggu karyawan LAN yang sedang browsing internet?

Kuncinya adalah memahami perbedaan fundamental antara Input Chain (Menuju Router) dan Forward Chain (Melintasi Router)!

Blok 2 - Konsep Inti & Definisi
Definisi 3 Default Filter Chains di MikroTik:

1. Input Chain: Menyaring paket data yang DITUJUKAN KE ROUTER ITU SENDIRI (misal: login Winbox, SSH, WebFig, ping ke IP router).
2. Forward Chain: Menyaring paket data yang MELINTASI ROUTER dari satu jaringan ke jaringan lain (misal: PC LAN membuka website YouTube di internet).
3. Output Chain: Menyaring paket data yang DIBUAT OLEH ROUTER DAN KELUAR (misal: router melakukan ping diagnostik atau sinkronisasi jam NTP).

Analogi Gerbang Masuk Istana Kerajaan:
  • Input Chain = Tamu yang ingin masuk ke dalam Kamar Pribadi Raja (Router). Penjagaan harus super ketat (Drop semua orang asing, hanya izinkan menteri/admin terpercaya).
  • Forward Chain = Pedagang rakyat yang hanya ingin Melintasi Jalan Raya Istana menuju pasar seberang (Internet). Asalkan barangnya sah, pedagang diizinkan lewat (Accept).

Blok 4 - Detail Teknis & Skrip Firewall Baku

4.1 Aturan Emas Stateful Firewall (FastTrack & Connection State):

️ Perangkat: MikroTik RouterOS v7 Menu: /ip firewall filter Tujuan: Menerapkan Template Firewall Standar Industri (Mencegah Brute Force)
/ip firewall filter (Baku) 
# === ATURAN INPUT CHAIN (MELINDUNGI ROUTER) ===
# 1. Izinkan koneksi yang sudah sah (Established & Related) - Hemat CPU:
/ip firewall filter add chain=input connection-state=established,related action=accept comment="Accept Established/Related"

# 2. Buang paket rusak (Invalid):
/ip firewall filter add chain=input connection-state=invalid action=drop comment="Drop Invalid"

# 3. Izinkan ICMP Ping untuk diagnostik:
/ip firewall filter add chain=input protocol=icmp action=accept comment="Accept Ping"

# 4. BLOKIR SEMUA AKSES LAIN DARI INTERNET WAN MENUJU ROUTER:
/ip firewall filter add chain=input in-interface=ether1-wan action=drop comment="Drop All Other from WAN"

# === ATURAN FORWARD CHAIN (MELINDUNGI JARINGAN LAN) ===
/ip firewall filter add chain=forward connection-state=established,related action=accept
/ip firewall filter add chain=forward connection-state=invalid action=drop
/ip firewall filter add chain=forward connection-nat-state=dstnat action=accept comment="Izinkan Dst-NAT Port Forward"
Blok 5 - Studi Kasus Nyata

Kasus: Mengatasi Kesalahan "Salah Pasang Drop di Forward Chain"

Analisis Kesalahan Siswa

Masalah: Seorang siswa ingin memblokir hacker agar tidak bisa membobol password Winbox router. Siswa tersebut mengetik perintah: /ip firewall filter add chain=forward in-interface=ether1 action=drop. Akibatnya, seluruh komputer di lab kantor tidak bisa browsing internet sama sekali!

1
Mengapa Internet Kantor Mati?

Paket browsing balasan dari Google datang dari ether1 (WAN) melintasi router menuju PC LAN. Karena siswa memasang drop di Forward Chain, paket balasan internet karyawan ikut terbunuh!

2
Perbaikan yang Benar:

Untuk mengamankan login router, ubah chain-nya menjadi chain=input, bukan forward!

Blok 6 - Quest Uji Pemahaman
Quest 1.3.6 • Pilihan Ganda 10 Poin

Jika administrator jaringan ingin memblokir akses remote SSH (Port 22) menuju router MikroTik dari arah internet publik WAN, chain manakah yang WAJIB digunakan pada rule firewall filter?

v Jawaban Benar: A (Chain Input)

Pembahasan: Karena paket SSH ditujukan KE ROUTER ITU SENDIRI sebagai tujuan akhir, lalu lintas tersebut masuk ke Chain Input.

Urutan baris pada Firewall Filter di MikroTik sangat menentukan! MikroTik membaca rule dari ATAS KE BAWAH. Jika kamu menaruh rule drop all di baris nomor 0 paling atas, semua rule di bawahnya tidak akan pernah dibaca dan router langsung terkunci.
